## 已确认系统事实

1. expanded 与 Lock Screen 是两套独立 presentation。Apple 只要求 Lock Screen 的布局与 expanded 类似，不保证逐像素、逐行、换行位置、截断位置或实际可见字符数一致。
2. 两套 presentation 当前均受约 84–160 pt 的系统展示高度和不同设备宽度约束。文字可能因字体、Dynamic Type、语言、手动换行和系统布局而分别截断。
3. 每条便签最多 240 个用户感知字符是 App 输入上限，不是系统完整显示保证。Live Activity 的静态与动态数据合计还受 4 KB 编码后数据限制；字符计数本身不能保证任意组合 Emoji 等内容一定低于该限制。
4. 用户可以禁用 Live Activities 或限制锁屏访问。系统可能按用户设置和隐私行为隐藏、redact 或移除展示。
5. “App 不主动隐藏或模糊正文”即使被选为产品策略，也只能描述产品自身的处理，不能成为“锁屏一定显示完整正文”的系统保证。

## 原承诺冲突

已有产品记录使用“锁屏展示的内容与灵动岛展开态一致”，并写明产品不额外隐藏或模糊正文。“一致”在这里混合了内容来源、内容状态与最终呈现三种不同含义，容易被理解为排版、截断位置和完整可见范围相同；后者超出产品对系统 presentation 的控制范围。240 个用户感知字符的输入规则也可能被误读成系统界面能够完整显示全部输入。

## 由系统事实推导出的产品限制

- 产品可以决定两套 presentation 使用哪一条便签和哪一种内容状态，但不能把相同排版、相同换行、相同截断位置或相同可见范围写成系统保证。
- 产品不能从 240 个用户感知字符的 App 输入规则推出内容必然低于 4 KB 或必然在 expanded、Lock Screen 中完整可见。
- 产品可以决定自身是否主动隐藏、模糊或概括正文，但不能覆盖用户设置、锁屏访问限制或系统隐私行为。
- 最终承诺必须把 App 可控的内容策略与系统决定的可见结果分开表述。

## 领域词汇

### 内容来源一致

expanded 与 Lock Screen 都取自同一条当前便签，而不是两份独立内容。

### 内容状态一致

产品不主动为 expanded 与 Lock Screen 提供不同的正文版本。

### 呈现一致

两套 presentation 的排版、换行、截断位置和实际可见范围相同。该概念不能作为系统保证，也不得用“内容一致”代替它。

### 完整可见

用户输入的全部内容都能在系统界面看到。该概念不能由 240 个用户感知字符的输入上限推出。

### 产品隐私策略

App 是否主动隐藏、模糊或概括正文的产品选择。

### 系统可见结果

用户设置、锁屏访问限制和系统行为共同决定的最终显示、redaction、隐藏或移除结果。

## 已确认产品决定

### 总承诺

expanded 与 Lock Screen 始终取自同一条当前便签、使用同一内容状态。产品尽量保持语义和信息顺序一致，但不承诺相同排版、相同截断位置或全文完整可见。240 个用户感知字符仅是 App 输入上限。App 是否主动隐藏正文由本票另行明确，但任何选择都不能覆盖用户设置和系统隐私行为。

确认记录：用户于 2026-07-31 回复“接受”。

### 场景检查

- 短文本：两处取自同一当前便签和同一内容状态；若系统空间充足，可以看到相同语义，但不把实际排版相同写成保证。
- 240 字长文本：App 仍允许输入最多 240 个用户感知字符；expanded 与 Lock Screen 均可以截断，不承诺全文完整可见。
- 手动换行、组合 Emoji、最大 Dynamic Type：仍保持同一内容来源和内容状态；换行、字符宽度、编码大小与系统布局可能导致两处可见范围不同。
- expanded 与 Lock Screen 截断位置不同：符合已确认承诺，不构成内容来源或内容状态不一致。
- 系统 redact 或用户禁用锁屏 Live Activities：属于系统可见结果变化，不构成产品违反内容来源和内容状态承诺。

### 产品隐私策略

App 不主动隐藏、模糊或概括正文；expanded 与 Lock Screen 均使用已经确认的同一内容状态。该决定只约束产品自身，不保证系统最终显示正文，也不覆盖用户设置、锁屏访问限制或系统隐私行为。

确认记录：用户于 2026-07-31 回复“确认”。

场景检查：若当前便签包含银行卡密码等敏感正文，而用户设置允许锁屏展示，App 不会主动遮盖或改写正文，旁观者可能看到内容；若系统对正文执行 redaction、隐藏或移除，则以系统可见结果为准。

## 待确认决策

无。用户已确认达到 shared understanding。

## 产品可以承诺的内容

- expanded 与 Lock Screen 始终取自同一条当前便签。
- 两套 presentation 使用同一内容状态，产品不主动提供不同正文版本。
- 产品尽量保持语义与信息顺序一致，但不承诺呈现一致。
- 240 个用户感知字符只作为 App 的输入容量上限，不作为系统完整显示或传输保证。
- App 不主动隐藏、模糊或概括正文。
- 产品隐私策略只约束 App 自身；系统可见结果仍由用户设置与系统行为共同决定。

## 明确禁止承诺的内容

- 不承诺 expanded 与 Lock Screen 的排版、换行、截断位置或实际可见范围相同。
- 不承诺最多 240 个用户感知字符会在 expanded 或 Lock Screen 全文完整可见。
- 不承诺 240 个用户感知字符本身必然满足 Live Activity 静态与动态数据合计 4 KB 的编码后限制。
- 不承诺锁屏一定显示正文，也不承诺正文在锁屏上一定不被 redact、隐藏或移除。
- 不承诺产品能够覆盖用户的 Live Activities 设置、锁屏访问设置或系统隐私行为。

## 自洽性检查场景

最终承诺须能同时解释以下场景，但不得借场景臆测真机结果：短文本、240 字长文本、手动换行、组合 Emoji、最大 Dynamic Type、expanded 与 Lock Screen 截断位置不同、锁屏正文被系统 redact、用户禁用锁屏 Live Activities。

## 仍需真机验证项

- 不同设备宽度与最大 Dynamic Type 下，expanded 和 Lock Screen 的实际换行、可见范围与截断位置。
- 短文本、240 字长文本、手动换行和组合 Emoji 在不同 presentation 中的实际显示差异。
- Always-On 与设备锁定/解锁状态下的最终显示行为。
- 锁屏访问设置变化后的最终显示、隐藏或移除结果。
- 系统 redaction 的实际触发与最终用户可见结果。
- 已确认的“不主动隐藏、模糊或概括正文”策略在 Lock Screen、Always-On 与 expanded 中的最终用户可见结果，以及它与“主动处理”对照条件的可见差异；对照仅用于验证，不作为备选产品策略。

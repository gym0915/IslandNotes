## Question

在 expanded 与 Lock Screen 是两套独立 presentation、都受 84–160 pt 布局限制，且锁屏还受用户隐私与禁用设置影响的前提下，MVP 应向用户承诺“同一份便签数据、尽量一致展示”，还是采用其他明确的内容与隐私边界？

讨论准备：

1. 从研究文件提取并固定以下事实，不把它们作为选择题问用户：
   - expanded 与 Lock Screen 是两套独立 presentation；Apple 只要求 Lock Screen 布局与 expanded 类似，不保证逐像素、逐行或实际可见字符数一致；
   - 两者当前均受约 84–160 pt 的系统展示高度及不同设备宽度约束，文字可能因字体、Dynamic Type、语言、手动换行和系统布局而分别截断；
   - 240 个用户感知字符是 App 输入上限，不是系统完整显示保证；Live Activity 的静态与动态数据合计还受 4 KB 编码后数据限制；
   - 用户可以禁用 Live Activities 或限制锁屏访问；系统可能按隐私设置隐藏、redact 或移除展示；
   - “App 不主动隐藏或模糊正文”只能描述产品自身的内容策略，不能成为“锁屏一定显示完整正文”的系统保证。
2. 新建决策记录：
   docs/decisions/records/system-presentation.md
3. 决策记录至少包含：文档状态、关联票据、事实来源、已确认系统事实、原承诺冲突、由系统事实推导出的产品限制、领域词汇、待确认决策、产品可以承诺的内容、明确禁止承诺的内容、交给视觉原型票的契约、仍需真机验证项和决策追溯表。
4. 明确区分并在文档中使用以下概念；若用户选择更好的名称，可以调整，但不得继续用“一致”同时指代不同含义：
   - 内容来源一致：expanded 与 Lock Screen 都来自同一条当前便签，而不是两份独立内容；
   - 内容状态一致：产品不主动为两个 presentation 提供不同正文版本；
   - 呈现一致：排版、换行、截断位置和实际可见范围相同；这不能作为系统保证；
   - 完整可见：用户输入的全部内容都能在系统界面看到；这不能由 240 字输入上限推出；
   - 产品隐私策略：App 是否主动隐藏、模糊或概括正文；
   - 系统可见结果：用户设置和系统行为共同决定的最终显示、redaction、隐藏或移除结果。
5. 决策记录只能写已确认事实和用户已经确认的决定。未确认项必须明确标记“待确认”，不能把推荐方案提前写成最终结论。

讨论方法：

1. 先向用户简洁复述冲突，再提出一个决定性问题并给出推荐答案。推荐起点应是：

## Conflict surfaced by research

- 已确认决定要求锁屏内容与灵动岛展开态一致，并且产品不主动隐藏或模糊正文。
- Apple 只要求 Lock Screen 使用与 expanded 类似的布局；两者的排版、换行、截断与实际可见字符数不受产品完全控制。
- 240 个用户感知字符是产品输入上限，不是系统完整显示保证；静态与动态 Activity 数据还必须合计不超过 4 KB。
- 用户的 Live Activities、锁屏访问和隐私设置可能隐藏、redact 或移除系统展示。

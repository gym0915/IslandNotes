# “灵动岛便签”MVP 设计

- 日期：2026-07-30
- 状态：已批准
- 项目代号：灵动岛便签
- 真机验收：iPhone 16 Pro，iOS 26.5.2

## 1. 产品目标

做一个原生 iPhone App，让用户把一张正在关注的列表型便签显示在灵动岛上。App 可以保存多张便签，但使用体验始终聚焦于当前便签，不建立便签首页、历史库或归档系统。

灵动岛是只读的快速查看入口。用户在 App 内编辑，灵动岛同步最新内容；点击展开后的灵动岛，返回对应便签的工作台。

## 2. MVP 范围

### 包含

- 创建、重命名和删除多张便签。
- 每张便签包含多条列表项。
- 新增、编辑、删除、勾选和拖拽排序列表项。
- 勾选完成后，列表项自动移动到列表底部。
- 通过轻量切换面板选择当前便签。
- 用户手动启动或停止当前便签的 Live Activity。
- 同一时间只允许一张便签显示在灵动岛。
- 本机持久化数据。
- 支持浅色与深色系统外观。

### 不包含

- 云同步、iCloud、账号或服务器。
- 通知、倒计时或定时提醒。
- 归档、历史记录或回收站。
- 灵动岛内勾选、删除、切换等操作。
- 正式产品名称和正式 Logo。开发阶段使用项目代号和占位图标。

## 3. 技术方案

采用全原生架构：

- SwiftUI：App 页面与 Widget Extension 视图。
- SwiftData：便签和列表项的本机持久化。
- ActivityKit：Live Activity 生命周期和内容同步。
- WidgetKit：灵动岛紧凑、最小与展开布局。
- URL / App deep link：从灵动岛打开指定便签。

此方案只维护一套 Swift 技术栈，满足真机交付，并为后续添加 iCloud 或桌面小组件保留清晰边界。

## 4. 信息架构与页面

### 4.1 当前便签工作台

App 启动后直接进入上次使用的便签工作台，不显示便签列表首页。

页面组成：

1. 顶部显示当前便签标题和便签切换入口。
2. 主体显示该便签的列表项。
3. 底部固定 Live Activity 主操作按钮。

列表交互：

- 点击列表项文字后原地编辑。
- 点击左侧圆圈后标记完成，并移到列表底部。
- 长按拖拽调整未完成项顺序。
- 左滑删除列表项。
- 列表末尾提供“添加一项”输入入口；按回车可连续添加。

Live Activity 操作：

- 未展示时，按钮文案为“显示在灵动岛”。
- 当前便签正在展示时，按钮文案为“停止显示”。
- 若另一张便签正在展示，对当前便签点击“显示在灵动岛”后，先结束原有 Activity，再启动当前便签。
- 切换 App 当前便签时，不自动改变灵动岛内容；必须由用户主动点击按钮。

### 4.2 便签切换面板

点击工作台顶部标题或切换入口，从底部弹出轻量面板。

- 面板只显示仍在使用的便签。
- 提供“新建便签”入口。
- 点击便签后关闭面板并切换工作台。
- 不提供归档或历史分区。
- 无用便签直接删除；删除前进行明确确认。
- 删除当前便签后，打开最近使用的另一张便签；若没有剩余便签，进入空白新建状态。

## 5. 灵动岛体验

### 5.1 紧凑与最小状态

- 在灵动岛侧边只显示 App Logo。
- 不显示标题、数量、进度或完成状态。
- 正式 Logo 确定前使用单色占位图标。

### 5.2 展开状态

- 展示当前 Live Activity 对应便签的标题与列表文字。
- 按便签当前顺序展示内容。
- 不按完成状态筛选，也不在灵动岛内强调完成状态。
- 不提供按钮、勾选、删除、切换或滚动操作。
- 根据系统提供的展开高度自适应；超出可用空间的内容直接截断，不显示“更多”或剩余数量。
- 点击展开后的灵动岛任意位置，通过 deep link 打开对应便签工作台。

### 5.3 同步与生命周期

- App 内每次完成有效修改后，先保存 SwiftData，再更新 Live Activity。
- 更新范围包含新增、编辑、删除、排序、勾选和标题修改。
- 如果所有列表项均已完成，Live Activity 继续展示，直到用户手动停止。
- 删除正在展示的便签时，同时结束 Live Activity。
- App 重启后识别系统中仍在运行的 Activity，并恢复正确的按钮状态。
- 如果系统已经结束 Activity，App 不伪造运行状态，按钮恢复为“显示在灵动岛”。
- Live Activity 的最终存续时间由 iOS 管理，App 不承诺永久常驻。

## 6. 数据模型

### Note

- `id: UUID`
- `title: String`
- `createdAt: Date`
- `updatedAt: Date`
- `lastOpenedAt: Date`
- 与多个 `NoteItem` 建立有序关系

### NoteItem

- `id: UUID`
- `text: String`
- `isCompleted: Bool`
- `sortOrder: Int`
- 所属 `Note`

### Live Activity 内容状态

- `noteID`
- `title`
- 按当前展示顺序编码的列表文字
- 用于识别内容版本的更新时间或 revision

App 只把渲染所需的快照交给 Activity，不让 Widget Extension 直接修改业务数据。

## 7. 状态流

### 启动展示

1. 用户在工作台点击“显示在灵动岛”。
2. App 结束可能存在的另一张便签 Activity。
3. App 从 SwiftData 生成当前便签快照。
4. ActivityKit 启动新的 Live Activity。
5. App 记录并展示实际运行状态。

### 编辑同步

1. 用户在工作台修改便签或列表项。
2. SwiftData 保存修改。
3. App 生成新的内容快照。
4. ActivityKit 更新对应 Activity。
5. 灵动岛刷新为最新内容。

### 点击返回

1. 用户点击展开后的灵动岛。
2. 系统打开包含 `noteID` 的 deep link。
3. App 查找该便签并设为当前便签。
4. 工作台显示对应内容。

## 8. 视觉设计系统

视觉依据来自用户提供的浅色与深色原型，提炼为原生、单色、柔和、宽松的设计语言。

### 8.1 语义颜色

统一定义并分别适配浅色、深色：

- `background`
- `surface`
- `surfaceElevated`
- `primaryText`
- `secondaryText`
- `separator`
- `primaryAction`
- `primaryActionText`

不引入装饰性色彩。层级主要由黑、白、中性灰和明度差表达。

### 8.2 形状与层级

- 大圆角分组卡片承载列表内容。
- 卡片尽量不使用阴影，依靠背景明度区分层级。
- 圆形按钮、便签切换面板等浮层使用细描边与柔和阴影。
- 主操作按钮使用黑白反转的全宽圆角样式。

### 8.3 排版与间距

- 使用 SF Pro 与 Dynamic Type。
- 标题使用克制的粗体，正文优先保证长时间阅读的清晰度。
- 次要信息使用语义灰色，不用缩小到难以阅读。
- 页面保持较大的左右留白、舒展的行高和明显的分组间距。

### 8.4 图标与动效

- 优先使用 SF Symbols，维持单色线性图标的一致线宽。
- 动效只服务于状态变化：面板弹出、列表重排、完成项下移和 Activity 状态切换。
- 使用系统感弹簧动画，并尊重“减少动态效果”设置。

原型中的 Mononote 名称和折角便签 Logo 不沿用；正式品牌另行设计。

## 9. 错误与边界处理

- Live Activities 不可用或未获系统允许时，主按钮给出明确但轻量的原因说明。
- SwiftData 保存失败时保留屏幕上的编辑内容，提示用户重试，不发送过期快照。
- Activity 更新失败时保留本地修改，并将按钮状态与系统真实状态对齐；后续编辑或用户重试时再次更新。
- deep link 指向已删除便签时，打开当前便签或空白新建状态，不崩溃。
- 空便签可以存在；灵动岛展开时至少显示便签标题，后续新增内容可即时同步。
- 系统压缩、截断或结束 Live Activity 属于预期边界，App 不以自定义常驻机制绕过系统限制。

## 10. 验证策略

### 单元测试

- 未完成项拖拽后的排序稳定性。
- 勾选后移动到底部，以及取消完成后的顺序规则。
- SwiftData 的创建、更新、删除和重启恢复。
- Note 到 Live Activity 内容快照的转换。
- Activity 切换、停止和系统已结束时的状态归一化。

### UI 测试

- 创建第一张和多张便签。
- 打开切换面板并切换当前便签。
- 新增、编辑、删除、勾选和拖拽列表项。
- 删除当前便签和删除正在展示的便签。
- 浅色、深色与较大 Dynamic Type 下的工作台布局。

### Live Activity 验收

- 模拟器检查各 Dynamic Island region 的基本布局与截断。
- 在 iPhone 16 Pro、iOS 26.5.2 上检查紧凑 Logo、展开内容、点击跳转和编辑后同步。
- 验证另一张便签替换、手动停止、App 重启和系统结束后的状态。

## 11. MVP 完成标准

当用户可以在真机上创建多张本地列表便签，直接在当前工作台编辑其中一张，手动把它显示到灵动岛，并可靠完成查看、截断、同步、跳转和停止的完整闭环时，MVP 视为完成。

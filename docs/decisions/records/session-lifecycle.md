# 灵动岛便签｜挂起生命周期决策

- 文档状态：已确认
- 决策票：[重新定义 Live Activity 的挂起生命周期](../tickets/06-session-lifecycle.md)
- 事实来源：[ActivityKit 与灵动岛系统约束研究](../../research/activitykit-system-constraints.md)
- 讨论方式：HITL grilling；一次只确认一个产品决定

## 已确认的系统事实

以下是 Apple 官方确认的系统事实，不是本票需要选择的产品决定：

1. 常规 Live Activity 最多活跃 8 小时。
2. 到达系统上限后，活动立即离开 Dynamic Island。
3. 活动结束后的内容最多还能在 Lock Screen 保留 4 小时。
4. 用户可以提前移除 Live Activity。
5. 用户可以在 Settings 中禁用 Live Activities。
6. 系统可能根据设备状态和并存活动决定实际 presentation；产品不能保证活动始终以预期形态出现在 Dynamic Island。

## 原有承诺与系统事实的冲突

现有产品模型承诺“挂起便签不会自动过期或消失”“持续保持挂起，直到用户主动取消、入库、删除或切换”“生命周期完全由用户手动控制”。这些承诺与 Live Activity 的 8 小时硬上限、用户可提前移除、用户可禁用以及系统控制实际 presentation 的事实冲突，必须被删除或重写，不能换一种文案继续承诺。

## 由系统事实推导出的产品限制

- App 中的便签数据可以长期保留；Live Activity 只能是这条便签在系统界面中的短期投影。
- Live Activity 被结束、移除或隐藏，不等于便签被删除、放入便签库、替换或失去内容。
- 便签的长期身份必须与 Live Activity 展示会话的短期身份分离。
- 产品不能承诺永久显示、只由用户结束、无缝连续展示或系统一定接受新的展示请求。

## 领域词汇

### 当前便签

App 工作台唯一槽位中、由 App 长期保存其身份和内容的便签。其存在与内容保留不依赖 Live Activity 是否展示。

### Live Activity 展示会话

将当前便签投影到系统界面的短期展示实例。它受系统时限、用户设置、用户移除和系统 presentation 决定约束。

### 挂起

用户显式启动一次有系统时限的 Live Activity 展示会话。一次挂起最长 8 小时，并可能因用户移除、用户禁用或系统限制而提前结束；它不表示永久常驻，也不表示系统展示结束后仍保留“挂起意图”。

## “挂起”的正式定义

“挂起”是用户在 App 中对当前便签执行的一次显式动作；该动作发起一段最长 8 小时、可能提前结束的 Live Activity 展示会话。挂起描述的是这段短期会话，不是便签的长期身份，也不是永久展示承诺。展示会话结束后，不再把便签称为“挂起中”。

## 便签长期状态与 Live Activity 展示会话的关系

便签是 App 长期保存的对象；挂起产生的 Live Activity 展示会话只是该便签的短期系统投影。展示会话是否存在不会改变便签身份；会话结束不会删除、入库、替换便签或使内容丢失。便签可以长期存在，但不能因此被描述为长期“挂起中”。

| --- | --- | --- | --- | --- | --- | --- | --- |
| 尚未启动展示会话 | 是 | 是 | 否 | 否 | 否 | 未挂起 | 可显式挂起 |
| 展示会话正常活跃 | 是 | 是 | 是 | 系统决定实际 presentation | 可能 | 挂起中 | 可编辑、取消、入库、删除或切换当前便签；重复挂起不改变会话 |

## 关键状态转换

| 起点 | 触发 | 结果 | 便签长期状态 |
| --- | --- | --- | --- |
| 未挂起 | 用户显式挂起且新会话成立 | 挂起中；开始一段新的最长 8 小时展示会话 | 同一条当前便签，内容保留 |
| 挂起中 | 达到 8 小时上限或 Activity 已确认提前结束 | 未挂起；上层语义为“展示会话已结束” | 同一条当前便签，内容保留 |
| 未挂起 | 用户显式再次挂起且新会话成立 | 挂起中；开始全新会话，不延续上一段 | 同一条当前便签，内容保留 |
| 挂起中 | 用户重复执行挂起 | 状态和当前会话均不变，不重置或延长 | 同一条当前便签，内容保留 |
| 挂起中 | 用户主动取消挂起 | 未挂起；结束当前展示会话 | 同一条当前便签，内容保留 |
| 挂起中 | 用户放入便签库 | 结束当前展示会话；原便签入库；新空白当前便签未挂起 | 原便签内容在便签库保留 |
| 挂起中 | 用户确认删除 | 结束当前展示会话；原便签删除；新空白当前便签未挂起 | 原便签内容不再保留 |
| 挂起中 | 用户从便签库切换当前便签 | 结束原会话后执行交换；新当前便签未挂起 | 两条便签按既有交换规则保留 |
| 挂起中 | 用户编辑当前便签 | 仍为挂起中；沿用同一展示会话 | 同一条当前便签，更新后的内容保留 |
| 挂起中 | 系统仅改变 presentation，但 Activity 仍活跃 | 仍为挂起中 | 同一条当前便签，内容保留 |
| 未挂起 | 系统仍残留已结束内容于 Lock Screen | 状态不变；残留不构成产品阶段 | 同一条当前便签，内容保留 |

## 8 小时上限的产品语义

Live Activity 达到 8 小时上限时，这次展示会话已经结束，当前便签立即进入“未挂起”状态。App 不保留“已到期”这一长期第三状态，也不保留挂起意图。便签仍是同一条当前便签，身份和内容完整保留；系统展示结束不会触发删除、入库或替换。

## Lock Screen 尾部展示的产品语义

产品状态以 Live Activity 是否活跃为准：活动活跃时是“挂起中”，活动结束时立即是“未挂起”。会话结束时，产品意图是同时结束 Dynamic Island 与 Lock Screen 展示，不主动保留或利用 Lock Screen 尾部，也不把尾部设计为有效展示阶段或独立产品状态。

Apple 允许已结束内容在 Lock Screen 最多残留 4 小时，因此产品不能承诺系统界面绝对即时消失。若系统仍短暂显示旧内容，只将其视为系统残留：它不代表活动仍然活跃，不得称为“挂起中”，也不改变 App 中便签的身份、内容或“未挂起”状态。

## 提前移除与正常到期的上层语义

正常达到 8 小时上限、用户主动移除、用户禁用 Live Activities 导致活动结束、系统提前结束以及其他已确认 Activity 不再活跃的情况，共享“展示会话已结束”这一上层语义；App 状态统一为“未挂起”。具体结束原因不形成多个长期产品状态，只供后续反馈与恢复规则使用。

无论结束原因是什么，当前便签仍完整保留，用户可以继续查看、编辑、入库、删除或尝试再次挂起。如果系统只是改变 presentation 或暂时没有在 Dynamic Island 展示，但 Live Activity 本身仍然活跃，产品状态仍是“挂起中”；不能仅凭 Dynamic Island 当前不可见判定会话结束。

如何检测 Activity 是否仍活跃、何时同步 App 状态、如何解释原因以及如何处理误差，全部移交异常与恢复票。

## 用户再次挂起的条件和边界

- 只有当前便签处于“未挂起”时，用户才能在 App 中显式发起再次挂起。
- 再次挂起创建一段全新的、最长 8 小时的展示会话，不恢复、延长或无缝衔接上一段会话。
- MVP 不限制再次挂起次数，也不设置冷却时间。
- MVP 不自动续挂，不在后台无缝创建下一段活动。
- 产品只承诺允许用户发起再次挂起的尝试，不承诺系统一定接受新请求。
- 当前已有活跃展示会话时，重复执行挂起不会创建、替换、重置或延长会话。
- 即使 Lock Screen 仍有上一段会话的系统残留，只要产品状态已经是“未挂起”，用户仍可尝试启动新会话。

## 取消、切换、入库、删除时的生命周期规则

- **主动取消挂起**：结束当前展示会话；便签继续作为当前便签完整保留，状态变为“未挂起”。
- **放入便签库**：若展示会话活跃，该操作同时结束会话；原便签进入便签库，工作台补入新的空白当前便签，新便签不自动挂起。
- **删除当前便签**：若展示会话活跃，该操作同时结束会话；确认删除后原便签不再保留，工作台补入新的空白当前便签，新便签不自动挂起。
- **从便签库切换当前便签**：若原当前便签的展示会话活跃，先结束该会话，再执行既有交换；新的当前便签不自动挂起。
- **挂起中编辑**：编辑的始终是同一条当前便签；展示会话身份不变，展示内容随该便签更新，不需要先取消再重新挂起。
- **展示会话正常或提前结束**：只改变当前便签的“挂起中／未挂起”状态，不会自动触发入库、删除、替换或切换。

上述规则保持三个不变量：当前便签与系统展示不能悄然成为两条便签；便签长期身份与展示会话短期身份分离；新的当前便签不会继承上一条便签的展示会话或自动挂起。

## 产品可以向用户作出的承诺

- 面向用户采用“静默生命周期”：用户只需要理解“挂起”和“取消挂起”，产品不主动解释展示会话、8 小时上限或正常结束原因。
- 用户执行挂起后，当前便签进入“挂起中”；Live Activity 结束后，当前便签直接回到“未挂起”。
- 正常生命周期结束时，不主动显示“已到期”“最长 8 小时”或“请重新挂起”等说明。
- 用户希望继续展示时，可以回到 App 再次执行“挂起”；每次都是新的展示会话。
- 便签内容由 App 长期保留，不因系统展示结束而丢失。
- 8 小时上限继续作为内部产品事实和领域约束，但不作为面向用户的主动说明。
- 启动失败、状态不一致或其他异常是否需要反馈，仍由异常与恢复票决定；“静默生命周期”不预先取消必要的异常反馈。

## 明确禁止作出的承诺

- 永久显示。
- 一直显示到用户主动取消。
- 系统一定不会提前移除或隐藏。
- 自动无缝续挂。
- Lock Screen 尾部一定完整保留 4 小时。
- 会话结束后 Lock Screen 一定绝对即时消失。
- 用户重新挂起一定成功。

## 移交给异常与恢复票的问题

以下问题继续由[确定挂起失败与系统中断后的恢复规则](../tickets/04-failure-recovery.md)处理，本票不作答：

- 如何检测 Live Activity 已结束、被移除、被隐藏或与 App 状态不一致。
- 何时显示错误或中断提示。
- 是否以及何时自动重试。
- App 重启、设备重启后的状态对账。
- 用户禁用 Live Activities 后的具体恢复步骤。
- 挂起请求、更新或结束失败时的恢复流程。

## 仍需真机验证的行为

- 首次请求的系统提示、时机和结果。
- Settings 中关闭 Live Activities 后，已有活动何时消失及重新开启后的行为。
- Activity 运行满 8 小时后离开 Dynamic Island 的实际时刻，以及 Lock Screen 尾部的实际保留时长。
- 用户手动移除后的系统状态变化及 App 可观察结果。
- App 被强制退出或设备重启前后，Activity 是否以及何时恢复。
- 多个 App 的 Live Activities 并存时，本活动实际 presentation 的变化。

| 顺序 | 决策 | 状态 | 依据 |
| --- | --- | --- | --- |
| 1 | “挂起”的用户承诺 | 已确认 | 挂起是用户显式启动的一次最长 8 小时、可能提前结束的 Live Activity 展示会话；不是永久常驻或长期挂起意图 |

| 4 | 用户再次挂起的边界 | 已确认 | 仅在未挂起时由用户显式创建新会话；不限次数、不设冷却、不自动续挂、不保证成功；活跃会话不被重复操作重置或延长 |

## Shared understanding

用户已明确确认上述七项决定已达到 shared understanding，可以据此关闭“重新定义 Live Activity 的挂起生命周期”。
